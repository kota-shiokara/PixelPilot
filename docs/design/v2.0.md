# PixelPilot v2.0 設計方針

> ステータス: Draft(方針合意済み・詳細設計前)

## 1. 背景

v1.0(2025-05)は Android 単体で Bluetooth HID マウスとして振る舞う最小実装だった。
接続先のハードコード、初期化タイミング、接続状態の不可視、機能不足(スクロール・キーボード無し)などの課題があり、
v2.0 では対象 OS・接続方式から設計を見直す。

## 2. プロダクトの基本方針

- **基本はモバイルアプリ単体**。HID プロトコルでマウス・キーボードの振る舞いを再現し、ホスト側にソフトのインストールを求めない。
- **デスクトップ版は高機能版**。OS 側での処理(アプリ起動・スクリプト・状態取得など)が必要な機能や、HID 直結できない端末のためにのみ使う。
- ユーザーの手間を最小化することを優先する。

## 3. 対象プラットフォーム

| 区分 | 対象 | サポート |
|---|---|---|
| クライアント | Android | 公式 |
| クライアント | iOS | 公式(デスクトップ版の接続が前提) |
| ホスト / デスクトップ版 | Windows, macOS | 公式 |
| ホスト / デスクトップ版 | Linux, ChromeOS, iPadOS など | ベストエフォート |

### iOS が HID 直結できない理由

- Bluetooth Classic: アプリから HID Device プロファイルを扱う公開 API が無い(Android の `BluetoothHidDevice` 相当が無い)。
- BLE: `CBPeripheralManager` で HID サービス(0x1812)を公開できない。バックグラウンドでのアドバタイズも制限される。
- USB: アプリが USB ガジェットとして振る舞う手段が無い。

そのため iOS 版は、デスクトップ版に接続して入力を代行してもらう形で提供する。

## 4. 機能範囲

### Standard(モバイル単体・Bluetooth HID)— v2.0 で全て提供

- マウス / タッチパッド(移動、クリック、スクロール、ドラッグ)
- キーボード
- メディアキー(Consumer Control)
- ショートカットパッド(キー組み合わせ・キー列の送信。Stream Deck ライク)

### デスクトップ版で追加される機能

- アプリ起動・スクリプト実行
- ホスト状態の反映(ミュート状態、アクティブアプリに応じたボタン切り替え等)
- 任意文字(Unicode / 日本語)入力
- クリップボード共有
- HID 直結できない端末(iOS など)への入力代行

## 5. 接続方式

| 経路 | 用途 | デスクトップ版 |
|---|---|---|
| Bluetooth Classic HID | Android → ホストへ入力を直接送る | 不要 |
| LAN(Wi-Fi) | クライアント ↔ デスクトップ版 | 必要 |
| USB(Android: AOA / iOS: usbmux) | クライアント ↔ デスクトップ版 | 必要 |

### USB について

- 非 root の Android は USB HID ガジェットになれない(ガジェット構成の変更にはシステム権限が必要)。
- `android.hardware.usb` の Accessory モード(`UsbManager.openAccessory()`)で、AOA プロトコルを話すデスクトップ版と通信する。
  PC からは HID ではなくベンダー固有デバイスとして見えるため、デスクトップ版が必須。
- iOS は usbmux 経由(iOS アプリはソケットで待ち受け、デスクトップ版が usbmux で接続)。
- Windows の AOA は WinUSB ドライバの割り当てが必要(インストーラで自動化する)。

## 6. デスクトップ版の役割切り替え

接続時のハンドシェイクで、クライアントが**能力**を申告する。OS 名ではなく能力で役割を決める。

```
Client → Desktop: Hello { platform: ANDROID, hidDirect: true,  ... }
Client → Desktop: Hello { platform: IOS,     hidDirect: false, ... }
```

| hidDirect | 入力の経路 | デスクトップ版の役割 |
|---|---|---|
| true | Bluetooth HID でホストへ直接(デスクトップ版を通さない) | 高機能版の機能のみ |
| false | デスクトップ版経由(LAN / USB) | 入力代行 + 高機能版の機能 |

- HID 直結時は入力経路にデスクトップ版を挟まないため、遅延が増えない。
- HID プロファイルが無効化された Android 端末も `hidDirect: false` として iOS と同じ経路で動作する。

## 7. アーキテクチャ

### 方針: 部品は共通、骨格は分離

Kotlin Multiplatform / Compose Multiplatform を使う。

- **共通化**: 入力イベント、ショートカット定義、プロトコル、タッチパッド・キーボード・ショートカットパッドの UI 部品
- **プラットフォーム別**: 画面遷移、オンボーディング、接続フロー

共通コードに `isIOS` のような分岐を持ち込まない。

### デスクトップ版が必須かどうかは利用可能な経路から導く

```kotlin
// commonMain
enum class TransportKind { BLUETOOTH_HID, AGENT_LAN, AGENT_USB }

interface PlatformTransports {
    fun available(): List<TransportKind> // 実行時に判定
}

val List<TransportKind>.requiresDesktop: Boolean
    get() = TransportKind.BLUETOOTH_HID !in this
```

- Android: `hidProfileSupported()` の結果に応じて `BLUETOOTH_HID` を含める
- iOS: `AGENT_LAN`, `AGENT_USB` のみ

### 入力イベントの共通表現

入力は **HID Usage コード**(キーコード、ボタン、ホイール)で表現する。

- Bluetooth HID 経路: そのまま HID レポートに変換して送信
- デスクトップ版経路: デスクトップ版が OS の入力 API(Windows `SendInput` / macOS `CGEvent`)に変換

### モジュール構成(案)

```
shared/
  core/            入力イベント(HID Usage)・ショートカット定義・プロトコル   … commonMain
  ui-components/   タッチパッド・キーボード・ショートカットパッド               … commonMain
  transport/
    api/           InputTransport, PlatformTransports                      … commonMain
    agent/         デスクトップ版との通信(LAN)                            … commonMain
    bluetooth-hid/ BluetoothHidDevice                                      … androidMain
    usb-aoa/       android.hardware.usb の Accessory モード                … androidMain
    usbmux/        待ち受けソケット                                         … iosMain
androidApp/        画面遷移・オンボーディング(BT ペアリング中心)
iosApp/            SwiftUI の骨格 + Compose 部品(ComposeUIViewController)
desktopApp/        エージェント(役割切り替え・入力注入・高機能版の機能)
```

### HID デバイス構成

マウス・キーボード・Consumer Control の複合デバイス(Report ID で区別)。

- マウス: 5 ボタン(左・右・中・戻る・進む)、X/Y、縦ホイール、横スクロール(AC Pan)
- キーボード: 修飾キー + 通常キー
- Consumer Control: 音量・再生制御など

## 8. 注意事項

- **キーボード配列**: HID は物理キー位置を送るため、ホストの配列(JIS / US)で記号の出方が変わる。Standard ではホスト配列を設定で選択させる。日本語などの任意文字入力はデスクトップ版の機能とする。
- **修飾キー**: Windows と macOS で Ctrl / ⌘ が異なる。ショートカット定義はホスト OS ごとに持てるようにする。
- **OS 権限**:
  - macOS: デスクトップ版にアクセシビリティ権限が必要
  - Windows: 管理者権限のウィンドウには通常権限から入力を注入できない(UIPI)
  - iOS: ローカルネットワーク利用許可(Bonjour での発見時)
  - Linux: Wayland 環境での入力注入は困難(ベストエフォート)
