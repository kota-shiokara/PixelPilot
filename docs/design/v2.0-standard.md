# PixelPilot v2.0 Standard 詳細設計(Android 単体)

> ステータス: Draft
>
> 上位方針: [v2.0 設計方針](./v2.0.md)

Standard は、Android 端末だけで Bluetooth HID としてホストを操作する構成である。デスクトップ版は使わない。
本書では、HID デバイスの構成、入力パイプライン、各機能の仕様、接続ライフサイクル、画面構成を定める。

## 1. 範囲

| 機能 | v2.0 |
|---|---|
| マウス / タッチパッド(移動・クリック・スクロール・ドラッグ) | ○ |
| キーボード | ○ |
| メディアキー(Consumer Control) | ○ |
| ショートカットパッド | ○ |

対象ホスト: Windows / macOS(公式)、その他(ベストエフォート)。

## 2. HID デバイス構成

キーボード・マウス・Consumer Control の複合デバイスとし、Report ID で区別する。
SDP の Subclass は `BluetoothHidDevice.SUBCLASS1_COMBO` とする。

| Report ID | 種別 | Input(ID を除く) | Output |
|---|---|---|---|
| 1 | キーボード | 8 バイト | 1 バイト(LED) |
| 2 | マウス | 7 バイト | なし |
| 3 | Consumer Control | 2 バイト | なし |

`BluetoothHidDevice.sendReport(device, id, data)` の `data` には Report ID を含めない。

### 2.1 キーボード(Report ID 1)

```
05 01        Usage Page (Generic Desktop)
09 06        Usage (Keyboard)
A1 01        Collection (Application)
85 01          Report ID (1)
05 07          Usage Page (Keyboard/Keypad)
19 E0 29 E7    Usage Min/Max (Left Control .. Right GUI)
15 00 25 01    Logical Min/Max (0, 1)
75 01 95 08    Report Size 1, Count 8
81 02          Input (Data, Var, Abs)          ; 修飾キー
95 01 75 08    Report Count 1, Size 8
81 01          Input (Const)                   ; 予約
95 05 75 01    Report Count 5, Size 1
05 08          Usage Page (LEDs)
19 01 29 05    Usage Min/Max (Num Lock .. Kana)
91 02          Output (Data, Var, Abs)         ; LED
95 01 75 03    Report Count 1, Size 3
91 01          Output (Const)                  ; パディング
95 06 75 08    Report Count 6, Size 8
15 00 26 FF 00 Logical Min/Max (0, 255)
05 07          Usage Page (Keyboard/Keypad)
19 00 29 FF    Usage Min/Max (0 .. 255)
81 00          Input (Data, Array, Abs)        ; キーコード ×6
C0           End Collection
```

- Input: `[修飾キー][予約][キー1..キー6]`
- 6 キーを超えて同時に押された場合は、キー欄すべてを `0x01`(ErrorRollOver)にする。
- Usage の上限を 0xFF にしているのは、JIS キー(International1〜5、LANG1/2)を送るため。
- Output(LED)は `BluetoothHidDevice.Callback` の `onSetReport` / `onInterruptData` で受け取り、Caps Lock などの表示に使う。


- Input: `[ボタン][X(LE 16bit)][Y(LE 16bit)][ホイール][横スクロール]`
- v1.0 は X/Y が 8 ビットだったため、速い移動で値が飽和していた。16 ビットにして、1 レポートで大きな移動量を送れるようにする。

### 2.3 Consumer Control(Report ID 3)

```
05 0C        Usage Page (Consumer)
09 01        Usage (Consumer Control)
A1 01        Collection (Application)
85 03          Report ID (3)
15 00 26 FF 03 Logical Min/Max (0, 0x3FF)
19 00 2A FF 03 Usage Min/Max (0 .. 0x3FF)
75 10 95 01    Report Size 16, Count 1
81 00          Input (Data, Array, Abs)
C0           End Collection
```

- Input: `[Usage(LE 16bit)]`。押下時に Usage、離した時に `0x0000` を送る。

| 機能 | Usage |
|---|---|
| 再生 / 一時停止 | 0x00CD |
| 次のトラック | 0x00B5 |
| 前のトラック | 0x00B6 |
| 停止 | 0x00B7 |
| ミュート | 0x00E2 |
| 音量アップ | 0x00E9 |
| 音量ダウン | 0x00EA |
| 画面の明るさ +/− | 0x006F / 0x0070(ホスト依存) |

## 3. 入力パイプライン

```
UI(ジェスチャー・キー操作)
  ↓ InputEvent(共通・HID Usage ベース)
InputTransport
  └ BluetoothHidTransport(androidMain)
       ↓ HidReportEncoder(共通・純 Kotlin)… 状態を保持し、レポートのバイト列を生成
       ↓ 送信キュー(専用スレッドで直列化)
     BluetoothHidDevice.sendReport
```

### 3.1 InputEvent(`shared/core`)

```kotlin
sealed interface InputEvent {
    data class PointerMove(val dx: Float, val dy: Float) : InputEvent
    data class Scroll(val vertical: Float, val horizontal: Float) : InputEvent
    data class MouseButton(val button: Button, val pressed: Boolean) : InputEvent
    data class Key(val usage: Int, val pressed: Boolean) : InputEvent        // Keyboard/Keypad Page
    data class Consumer(val usage: Int, val pressed: Boolean) : InputEvent   // Consumer Page
}
```

デスクトップ版経由の経路でも同じ `InputEvent` を流す。デスクトップ版はこれを OS の入力 API に変換する。

### 3.2 HidReportEncoder(`shared/hid`)

- 押下中のボタン・修飾キー・キー(最大 6)を状態として持ち、イベントごとに該当レポートを生成する。
- **移動・スクロールは浮動小数で蓄積し、整数部だけを送って端数は持ち越す。** ゆっくり動かしても移動が失われないようにする(v1.0 の課題)。
- 16 ビットの範囲を超える移動量は、複数のレポートに分割する。
- Android に依存しない純 Kotlin とし、JVM の単体テストで検証する。

### 3.3 送信

- 送信は専用のシングルスレッドで直列化する(UI スレッドで `sendReport` を呼ばない)。
- 移動・スクロールは一定間隔(約 8ms)ごとにまとめて 1 レポートで送る。ボタン・キーのイベントは即時に送り、その前に蓄積中の移動を吐き出して順序を保つ。
- クリックは押下レポートと解放レポートを分けて送る(v1.0 と同じ)。

## 4. マウス / タッチパッド

### 4.1 ジェスチャー

| 操作 | 動作 |
|---|---|
| 1 本指ドラッグ | カーソル移動 |
| 1 本指タップ | 左クリック |
| 2 本指タップ | 右クリック |
| 3 本指タップ | 中クリック |
| 2 本指ドラッグ | スクロール(縦・横) |
| タップ直後に押したままドラッグ | ドラッグ&ドロップ(左ボタン押下を維持) |
| 画面下部のボタン | 左・右・中クリック(押している間ボタン押下を維持) |

ジェスチャー解釈(`TouchpadInterpreter`)は、タッチ点の列から `InputEvent` を生成する純 Kotlin のロジックにする。Compose からはタッチ点を渡すだけにして、単体テストできるようにする。

### 4.2 設定

- 移動感度、加速の有無(速く動かすほど移動量を増やす曲線)
- スクロール速度、スクロール方向(ナチュラル / 従来)
- 触覚フィードバック(クリック時)

## 5. キーボード

### 5.1 ホストのキーボード配列

HID は物理キー位置を送るため、ホストの配列に合わせて文字をキーに変換する必要がある。
ホストごとに配列(US / JIS)を設定で選ぶ。

```kotlin
interface KeyboardLayout {
    /** 文字を (Usage, 修飾キー) に変換する。配列で入力できない文字は null */
    fun strokeOf(c: Char): KeyStroke?
}
```

例: `@` は US 配列では Shift + `2`(0x1F)、JIS 配列では `@` キー(0x2F)。

JIS 固有キー: 半角/全角 = 0x35、¥ = International3(0x89)、ろ = International1(0x87)、変換 = International4(0x8A)、無変換 = International5(0x8B)、かな = International2(0x88)。macOS の英数 / かなは LANG2(0x91)/ LANG1(0x90)。

### 5.2 入力方式

| 方式 | 内容 | 用途 |
|---|---|---|
| アプリ独自のキー配列 | アプリ内に描画したキーボード。キーごとに Usage を直接送る | 通常の入力、ショートカット、修飾キーの組み合わせ |
| テキスト送信 | 入力欄に打った文字列を、配列に従ってキー列に変換して送る | まとまった ASCII 文字列の入力 |

- 日本語は HID で直接送れない。ホスト側の IME を使ってローマ字で入力する(アプリ独自のキー配列で打つ)。任意文字の直接入力はデスクトップ版の機能とする。
- テキスト送信で配列に存在しない文字が含まれる場合は、送信前に警告する。
- 特殊キー列: Esc、Tab、矢印、Home / End / PageUp / PageDown、Delete、F1〜F12。
- 修飾キー(Ctrl / Shift / Alt / Win・⌘)はトグル式(次のキーを押すまで保持、長押しで固定)。ラベルはホスト OS の設定(Windows / macOS)に合わせて切り替える。

## 6. ショートカットパッド

Stream Deck のように、ボタンに操作を割り当てて送る。HID だけで完結する操作に限る。

### 6.1 データモデル(`shared/core`)

```kotlin
@Serializable
data class ShortcutPad(val id: String, val name: String, val pages: List<ShortcutPage>)

@Serializable
data class ShortcutPage(val name: String, val columns: Int, val buttons: List<ShortcutButton>)

@Serializable
data class ShortcutButton(val label: String, val icon: String?, val action: ShortcutAction)

@Serializable
sealed interface ShortcutAction {
    data class KeyCombo(val modifiers: Set<Modifier>, val usage: Int) : ShortcutAction
    data class KeySequence(val steps: List<Step>) : ShortcutAction   // キー操作と待機の列
    data class Text(val text: String) : ShortcutAction               // ホスト配列で変換して送る
    data class ConsumerKey(val usage: Int) : ShortcutAction
}
```

- 保存形式は JSON(kotlinx.serialization)。インポート / エクスポートできるようにし、パッドを共有できるようにする。
- デスクトップ版の機能(アプリ起動など)を追加するときは、`ShortcutAction` にアクションを足す。Standard では、そのアクションを実行できない経路として扱い、ボタンを無効表示にする。
- Windows 用・macOS 用のプリセット(コピー、貼り付け、スクリーンショット、仮想デスクトップ切り替えなど)を同梱する。

## 7. 接続ライフサイクル(Android)

### 7.1 状態

```kotlin
sealed interface ConnectionState {
    data object PermissionRequired
    data object BluetoothOff
    data object Unsupported                      // HID Device プロファイルが使えない
    data object Registering
    data object Ready                            // 登録済み・未接続
    data class Connecting(val host: HostDevice)
    data class Connected(val host: HostDevice)
    data class Error(val reason: ErrorReason)
}
```

UI はこの状態を描画するだけにする。v1.0 の初期化前アクセスや、権限の結果を待たない問題をなくす。

### 7.2 流れ

1. 権限を要求し、結果を待つ(Android 12 以降: `BLUETOOTH_CONNECT` / `BLUETOOTH_ADVERTISE`、Android 11 以前: `BLUETOOTH` / `BLUETOOTH_ADMIN`)。
2. Bluetooth が OFF なら、有効化を促す。
3. `getProfileProxy(HID_DEVICE)` で HID Device プロファイルを取得する。取得できない、または一定時間応答がない場合は `Unsupported` とし、`PlatformTransports.available()` から `BLUETOOTH_HID` を外す。
4. `registerApp` で HID アプリを登録し、`onAppStatusChanged(registered = true)` を待って `Ready` にする。
5. 接続先を決める。
   - 前回接続したホストがあれば、自動で接続する。
   - ペアリング済み機器の一覧から選ぶ。
   - 新しいホストの場合は、`ACTION_REQUEST_DISCOVERABLE` で端末を検出可能にし、ホスト側の Bluetooth 設定からペアリングしてもらう。ホスト OS ごとの手順をアプリ内で案内する。
6. `onConnectionStateChanged` で `Connecting` / `Connected` に遷移する。切断時は `Ready` に戻り、前回のホストに再接続を試みる。

- 接続先の機器名をハードコードしない(v1.0 の課題)。接続したホストのアドレスを DataStore に保存する。
- アプリ終了時は `unregisterApp` を呼び、プロファイルプロキシを閉じる。

### 7.3 フォアグラウンドサービス(提案)

HID アプリの登録と接続を、フォアグラウンドサービス(type `connectedDevice`)で保持する。
画面オフや他アプリへの切り替えでも接続が切れないようにするため。UI はサービスにバインドして状態を受け取る。

- 追加の権限: `FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_CONNECTED_DEVICE`、`POST_NOTIFICATIONS`(Android 13 以降)
- 通知から切断できるようにする。

## 8. 画面構成(Android)

```
オンボーディング
  権限 → HID 対応チェック → ホストとのペアリング案内(ホスト OS 別)
    ↓
ホスト選択(前回のホスト / ペアリング済み一覧 / 新規ペアリング)
    ↓
メイン(上部に接続状態、下部にタブ)
  ├ タッチパッド
  ├ キーボード
  ├ ショートカットパッド
  └ メディア
設定
  ホストごと: OS(Windows / macOS / その他)、キーボード配列(US / JIS)
  共通: 感度、加速、スクロール方向・速度、触覚フィードバック
```

- タッチパッド・キーボード・ショートカットパッド・メディアの各画面は `shared/ui-components` に置き、iOS 版と共有する。
- オンボーディング・ホスト選択・画面遷移は `androidApp` に置く。

## 9. モジュール対応

| モジュール | 本書で定める内容 |
|---|---|
| `shared/core` | `InputEvent`、HID Usage 定数、`KeyboardLayout`(US / JIS)、ショートカットのデータモデル |
| `shared/hid`(新設) | Report Descriptor、`HidReportEncoder` |
| `shared/ui-components` | タッチパッド、キーボード、ショートカットパッド、メディアの UI、`TouchpadInterpreter` |
| `shared/transport/api` | `InputTransport`、`PlatformTransports` |
| `shared/transport/bluetooth-hid` | `BluetoothHidDevice` の制御、`ConnectionState`、フォアグラウンドサービス |
| `androidApp` | オンボーディング、ホスト選択、画面遷移、設定画面 |

`shared/hid` は Android 専用の経路でしか使わないが、純 Kotlin のため commonMain に置き、JVM で単体テストする。

## 10. テスト

- Report Descriptor: バイト列のゴールデンテスト(各レポート長の検算を含む)
- `HidReportEncoder`: 端数の持ち越し、16 ビット超の分割、6 キー超のロールオーバー、押下 / 解放の順序
- `TouchpadInterpreter`: 各ジェスチャーの判定(タップとドラッグの閾値、2 本指・3 本指)
- `KeyboardLayout`: US / JIS の ASCII 全文字の変換表
- 実機テスト: Windows 11 / macOS(最新)への接続、各機能の動作

## 11. マイルストーン(案)

1. KMP プロジェクトの骨組み、`shared/core`・`shared/hid`、接続ライフサイクル、タッチパッド

3. メディアキー、ショートカットパッド(プリセット、インポート / エクスポート)
4. オンボーディング、設定、フォアグラウンドサービス、仕上げ
