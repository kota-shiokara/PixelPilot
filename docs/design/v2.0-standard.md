# PixelPilot v2.0 Standard 詳細設計(Android 単体)

> ステータス: Draft
>
> 上位方針: [v2.0 設計方針](./v2.0.md)

Standard は、Android 端末だけで Bluetooth HID としてホストを操作する構成である。デスクトップ版は使わない。
本書では、HID デバイスの構成、入力パイプライン、各機能の仕様、接続ライフサイクル、画面構成を定める。

v2.0 は **v1.0 Android アプリの置き換え(MVP)** とし、マウスとキーボードに絞る。v2.x の項目も設計は本書に残し、該当箇所に「v2.x」と明記する。

## 1. 範囲

| 機能 | 提供時期 |
|---|---|
| マウス(移動・クリック・スクロール・ドラッグ) | v2.0 |
| キーボード(アプリ内のキー配列、US / JIS) | v2.0 |
| メディアキー(Consumer Control) | v2.x(Report Descriptor には v2.0 から含める) |
| ショートカットパッド | v2.x |
| IME(仮想キーボード)入力・テキスト送信 | v2.x |
| バックグラウンド時の接続保持 | v2.x |
| 英語表示 | v2.x(v2.0 は日本語のみ) |
| 横向き表示 | v2.x(v2.0 は縦固定) |
| 物理キーボードからの入力 | 対応しない(13. 決定事項 6) |

対象ホスト: Windows / macOS(公式)、その他(ベストエフォート)。

## 2. HID デバイス構成

キーボード・マウス・Consumer Control の複合デバイスとし、Report ID で区別する。
SDP の Subclass は `BluetoothHidDevice.SUBCLASS1_COMBO` とする。

| Report ID | 種別 | Input(ID を除く) | Output |
|---|---|---|---|
| 1 | キーボード | 8 バイト | 1 バイト(LED) |
| 2 | マウス | 7 バイト | なし |
| 3 | Consumer Control | 2 バイト | なし |

`BluetoothHidDevice.sendReport(device, id, data)` の `data` には Report ID を含めない。

### 2.1 キーボード(Report ID 1)

```

09 06        Usage (Keyboard)
A1 01        Collection (Application)
85 01          Report ID (1)
05 07          Usage Page (Keyboard/Keypad)
19 E0 29 E7    Usage Min/Max (Left Control .. Right GUI)
15 00 25 01    Logical Min/Max (0, 1)
75 01 95 08    Report Size 1, Count 8
81 02          Input (Data, Var, Abs)          ; 修飾キー
95 01 75 08    Report Count 1, Size 8
81 01          Input (Const)                   ; 予約
95 05 75 01    Report Count 5, Size 1
05 08          Usage Page (LEDs)
19 01 29 05    Usage Min/Max (Num Lock .. Kana)
91 02          Output (Data, Var, Abs)         ; LED
95 01 75 03    Report Count 1, Size 3
91 01          Output (Const)                  ; パディング
95 06 75 08    Report Count 6, Size 8
15 00 26 FF 00 Logical Min/Max (0, 255)
05 07          Usage Page (Keyboard/Keypad)
19 00 29 FF    Usage Min/Max (0 .. 255)
81 00          Input (Data, Array, Abs)        ; キーコード ×6
C0           End Collection
```

- Input: `[修飾キー][予約][キー1..キー6]`
- 6 キーを超えて同時に押された場合は、キー欄すべてを `0x01`(ErrorRollOver)にする。
- Usage の上限を 0xFF にしているのは、JIS キー(International1〜5、LANG1/2)を送るため。
- Output(LED)は `BluetoothHidDevice.Callback` の `onSetReport` / `onInterruptData` で受け取り、Caps Lock などの表示に使う。

- Input: `[ボタン][X(LE 16bit)][Y(LE 16bit)][ホイール][横スクロール]`

### 2.3 Consumer Control(Report ID 3)

```
05 0C        Usage Page (Consumer)
09 01        Usage (Consumer Control)
A1 01        Collection (Application)
85 03          Report ID (3)
15 00 26 FF 03 Logical Min/Max (0, 0x3FF)
19 00 2A FF 03 Usage Min/Max (0 .. 0x3FF)
75 10 95 01    Report Size 16, Count 1
81 00          Input (Data, Array, Abs)
C0           End Collection
```

- Input: `[Usage(LE 16bit)]`。押下時に Usage、離した時に `0x0000` を送る。
- メディアキーの UI は v2.x だが、Report Descriptor には v2.0 から含める。後から Descriptor を変えると、ホスト側で再ペアリングが必要になることがあるため。

| 機能 | Usage |
|---|---|
| 再生 / 一時停止 | 0x00CD |
| 次のトラック | 0x00B5 |
| 前のトラック | 0x00B6 |
| 停止 | 0x00B7 |
| ミュート | 0x00E2 |
| 音量アップ | 0x00E9 |
| 音量ダウン | 0x00EA |
| 画面の明るさ +/− | 0x006F / 0x0070(ホスト依存) |

## 3. 入力パイプライン

```
UI(ジェスチャー・キー操作)
  ↓ InputEvent(共通・HID Usage ベース)
InputTransport
  └ BluetoothHidTransport(androidMain)
       ↓ HidReportEncoder(共通・純 Kotlin)… 状態を保持し、レポートのバイト列を生成
       ↓ 送信キュー(専用スレッドで直列化)
     BluetoothHidDevice.sendReport
```

### 3.1 InputEvent(`model/input`)

```kotlin
sealed interface InputEvent {
    data class PointerMove(val dx: Float, val dy: Float) : InputEvent
    data class Scroll(val vertical: Float, val horizontal: Float) : InputEvent
    data class MouseButton(val button: Button, val pressed: Boolean) : InputEvent
    data class Key(val usage: Int, val pressed: Boolean) : InputEvent        // Keyboard/Keypad Page
    data class Consumer(val usage: Int, val pressed: Boolean) : InputEvent   // Consumer Page
}
```

デスクトップ版経由の経路でも同じ `InputEvent` を流す。デスクトップ版はこれを OS の入力 API に変換する。

### 3.2 HidReportEncoder(`domain/hid`)

- 押下中のボタン・修飾キー・キー(最大 6)を状態として持ち、イベントごとに該当レポートを生成する。
- **移動・スクロールは浮動小数で蓄積し、整数部だけを送って端数は持ち越す。** ゆっくり動かしても移動が失われないようにする(v1.0 の課題)。
- 16 ビットの範囲を超える移動量は、複数のレポートに分割する。
- Android に依存しない純 Kotlin とし、JVM の単体テストで検証する。

### 3.3 送信

- 送信は専用のシングルスレッドで直列化する(UI スレッドで `sendReport` を呼ばない)。
- 移動・スクロールは一定間隔(約 8ms)ごとにまとめて 1 レポートで送る。ボタン・キーのイベントは即時に送り、その前に蓄積中の移動を吐き出して順序を保つ。
- クリックは押下レポートと解放レポートを分けて送る(v1.0 と同じ)。

## 4. マウス

画面・タブに出す機能名は **「マウス」**(英語: Mouse)とする。「キーボード」と同じく、PC から見た役割で呼ぶ。
タッチ入力を解釈するロジックは、スマホ上の操作を扱うため `TouchpadInterpreter` の名前のままとする。

### 4.1 ジェスチャー

| 操作 | 動作 |
|---|---|
| 1 本指ドラッグ | カーソル移動 |
| 1 本指タップ | 左クリック |
| 1 本指の素早い 2 回タップ | ダブルクリック |
| 2 本指タップ | 右クリック |
| 3 本指タップ | 中クリック |
| 2 本指ドラッグ | スクロール(縦・横) |
| タップ直後に押したままドラッグ | ドラッグ&ドロップ(左ボタン押下を維持) |
| 1 本指で長押し(500ms) | 操作ダイアル: ずらして離すと 戻る(左)・進む(右)・中クリック(上)・右クリック(下) |
| 画面下部のボタン | 左・右・中クリック(押している間ボタン押下を維持) |

ジェスチャー解釈(`TouchpadInterpreter`)は、タッチ点の列から `InputEvent` を生成する純 Kotlin のロジックにする。Compose からはタッチ点を渡すだけにして、単体テストできるようにする。

操作ダイアル(#98)は、指の位置を中心に、リングを 4 つの弧に分けた形で出す(画面デザインの仮案「2-b」)。開いたときに軽く振動させる。中央付近で離すとキャンセル。タップ直後のもう一度のタッチではドラッグを優先して開かない。マウスのサブボタン(戻る・進む)は、このダイアルだけで送る(2 本指の左右は横スクロールと区別できないため使わない)。

画面下部のクリックボタンは**既定で表示**し、設定で非表示にできる。非表示にした場合もすべての操作をジェスチャーだけで行えるよう、ボタンでできる操作(左・右・中クリック、ドラッグ)はジェスチャーでも必ず行えるようにする。

### 4.2 設定

| 項目 | 提供時期 |
|---|---|
| 移動感度 | v2.0 |
| スクロール方向(ナチュラル / 従来) | v2.0 |
| クリックボタンの表示(既定: 表示) | v2.0 |
| 加速の有無(速く動かすほど移動量を増やす曲線) | v2.x |
| スクロール速度 | v2.x |
| 触覚フィードバック(クリック時) | v2.x |

### 4.3 画面

- 操作面はできるだけ広く取る。上部に帯(ヘッダー)は置かない。
- 接続状態は操作面の左上に小さく重ねて表示する(タッチは透過させる)。
  - 接続中: 緑の丸 + 接続先の名前
  - 切断・エラー: 赤の丸 + エラーの内容
  - 色だけに頼らず、文言でも状態が分かるようにする。
- 設定画面へは、下部のタブ列(マウス / キーボード / 設定)から行く。
- 画面の左右端には余白を残す。Android のジェスチャーナビゲーションでは、画面端からのスワイプが「戻る」に割り当てられており、操作面と取り合うため。余白の幅は実機で調整する。
- 操作のヒント(1 本指: 移動 など)を操作面に薄く表示する。

## 5. キーボード

### 5.1 ホストのキーボード配列

HID は物理キー位置を送るため、ホストの配列に合わせて文字をキーに変換する必要がある。
ホストごとに配列(US / JIS)を設定で選ぶ。

```kotlin
interface KeyboardLayout {
    /** 文字を (Usage, 修飾キー) に変換する。配列で入力できない文字は null */
    fun strokeOf(c: Char): KeyStroke?
}
```

例: `@` は US 配列では Shift + `2`(0x1F)、JIS 配列では `@` キー(0x2F)。

JIS 固有キー: 半角/全角 = 0x35、¥ = International3(0x89)、ろ = International1(0x87)、変換 = International4(0x8A)、無変換 = International5(0x8B)、かな = International2(0x88)。macOS の英数 / かなは LANG2(0x91)/ LANG1(0x90)。

### 5.2 入力方式

| 方式 | 内容 | 提供時期 |
|---|---|---|
| アプリ内のキー配列(既定) | アプリ内に描画したキーボード。キーごとに Usage を直接送る | v2.0 |
| IME(仮想キーボード)入力 | Gboard などの IME で打った文字を、配列に従ってキー列に変換して送る。オプション(既定オフ) | v2.x |
| テキスト送信 | 入力欄に打った文字列を、配列に従ってキー列に変換してまとめて送る | v2.x |
| 物理キーボード | 対応しない(13. 決定事項 6) | — |

- 既定をアプリ内のキー配列にするのは、キーボード画面を開くたびに IME が起動すると煩わしいため。
- 日本語は HID で直接送れない。ホスト側の IME を使ってローマ字で入力する(アプリ内のキー配列で打つ)。任意文字の直接入力はデスクトップ版の機能とする。
- 特殊キー列: Esc、Tab、矢印、Home / End / PageUp / PageDown、Delete、F1〜F12。
- 修飾キー(Ctrl / Shift / Alt / Win・⌘)はトグル式(次のキーを押すまで保持、長押しで固定)。ラベルはホスト OS の設定(Windows / macOS)に合わせて切り替える。
- 記号: 最下段の「英数」キーの左に「記号」キーを置き、押すと文字キーの部分が記号の配列に切り替わる。もう一度押すと文字に戻る。
- 特殊キー・修飾キーの列は文字キーと分けて部品にする。v2.x の IME 入力で、IME の上にも表示するため。

IME 入力(v2.x)の注意点:

- IME はキーではなく文字を渡してくる(`commitText`)ため、`KeyboardLayout` で (Usage, 修飾キー) に変換して送る。
- 予測変換・自動修正を抑える(`TYPE_TEXT_VARIATION_VISIBLE_PASSWORD`、`TYPE_TEXT_FLAG_NO_SUGGESTIONS`、`IME_FLAG_FORCE_ASCII`)。置き換えが起きた場合は、削除をバックスペースに変換する。
- 日本語 IME の変換中の文字は送らず、確定した文字だけを送る。
- 入力欄が空だとバックスペースを通知しない IME があるため、独自の `InputConnection` を使う。
- IME ではキーの押しっぱなし(キーリピート)を扱えない。
- テキスト送信で配列に存在しない文字が含まれる場合は、送信前に警告する。

## 6. ショートカットパッド(v2.x)

Stream Deck のように、ボタンに操作を割り当てて送る。HID だけで完結する操作に限る。

### 6.1 データモデル(`model/shortcut`)

```kotlin
@Serializable
data class ShortcutPad(val id: String, val name: String, val pages: List<ShortcutPage>)

@Serializable
data class ShortcutPage(val name: String, val columns: Int, val buttons: List<ShortcutButton>)

@Serializable
data class ShortcutButton(val label: String, val icon: String?, val action: ShortcutAction)

@Serializable
sealed interface ShortcutAction {
    data class KeyCombo(val modifiers: Set<Modifier>, val usage: Int) : ShortcutAction
    data class KeySequence(val steps: List<Step>) : ShortcutAction   // キー操作と待機の列
    data class Text(val text: String) : ShortcutAction               // ホスト配列で変換して送る
    data class ConsumerKey(val usage: Int) : ShortcutAction
}
```

- 保存形式は JSON(kotlinx.serialization)。インポート / エクスポートできるようにし、パッドを共有できるようにする。
- デスクトップ版の機能(アプリ起動など)を追加するときは、`ShortcutAction` にアクションを足す。Standard では、そのアクションを実行できない経路として扱い、ボタンを無効表示にする。
- Windows 用・macOS 用のプリセット(コピー、貼り付け、スクリーンショット、仮想デスクトップ切り替えなど)を同梱する。

## 7. 接続ライフサイクル(Android)

### 7.1 状態

```kotlin
sealed interface ConnectionState {
    data object PermissionRequired
    data object BluetoothOff
    data object Unsupported                      // HID Device プロファイルが使えない
    data object Registering
    data object Ready                            // 登録済み・未接続
    data class Connecting(val host: HostDevice)
    data class Connected(val host: HostDevice)
    data class Error(val reason: ErrorReason)
}
```

UI はこの状態を描画するだけにする。v1.0 の初期化前アクセスや、権限の結果を待たない問題をなくす。

`ConnectionState` は **Bluetooth HID 経路の状態**であり、アプリ全体の状態ではない。

- ホスト選択画面は、`PlatformTransports.available()` が返す経路ごとにカードを出し、各カードの中でその経路の状態を表示する。
- ある経路が使えなくても(例: Bluetooth HID 非対応)、他の経路(v2.x の USB など)が使えればアプリは使える。「この端末では使えません」とするのは、使える経路が一つも無い場合だけ。
- 経路ごとの判断は OS 名ではなく、経路の有無と状態で行う(共通コードに OS 分岐を持ち込まない)。

### 7.2 流れ

1. 権限を要求し、結果を待つ(Android 12 以降: `BLUETOOTH_CONNECT` / `BLUETOOTH_ADVERTISE`、Android 11 以前: `BLUETOOTH` / `BLUETOOTH_ADMIN`)。
2. Bluetooth が OFF なら、有効化を促す。
3. `getProfileProxy(HID_DEVICE)` で HID Device プロファイルを取得する。取得できない、または一定時間応答がない場合は `Unsupported` とし、`PlatformTransports.available()` から `BLUETOOTH_HID` を外す。
4. `registerApp` で HID アプリを登録し、`onAppStatusChanged(registered = true)` を待って `Ready` にする。
5. 接続先を決める。
   - 前回接続したホストがあれば、自動で接続する。
   - ペアリング済み機器の一覧から選ぶ。
   - 新しいホストの場合は、`ACTION_REQUEST_DISCOVERABLE` で端末を検出可能にし、ホスト側の Bluetooth 設定からペアリングしてもらう。ホスト OS ごとの手順をアプリ内で案内する。
6. `onConnectionStateChanged` で `Connecting` / `Connected` に遷移する。接続中に切れた場合は `Error(CONNECTION_LOST)`(「接続が切れました(再接続中…)」、7.5)とし、前回のホストに再接続を試みる。接続しようとしていたホストにつながらなかった場合は `Error(HOST_NOT_FOUND)`。

- 接続先の機器名をハードコードしない(v1.0 の課題)。接続したホストのアドレスを DataStore に保存する。
- アプリ終了時は `unregisterApp` を呼び、プロファイルプロキシを閉じる。

### 7.3 画面を点けたままにする(v2.0)

v2.0 ではバックグラウンド時の接続保持(7.4)を行わないため、画面がスリープすると接続が切れる可能性が高い。
そのため、マウス画面とキーボード画面を開いている間は画面を点けたままにする(`FLAG_KEEP_SCREEN_ON`)。

- 設定でオン・オフを切り替えられるようにする(既定: オン)。電池の消費とのトレードオフのため。
- バックグラウンドに回って切断された場合は、フォアグラウンドに戻ったときに自動で再登録し、前回のホストへ再接続する。

### 7.4 バックグラウンド時の接続保持(v2.x)

**方針: 短時間だけ保持し、常駐はさせない。フォアグラウンドに戻ったら自動で再開する。**

アプリがバックグラウンドに回ると、プロセスはキャッシュ状態になり、凍結(cached apps freezer)や終了の対象になる。
凍結中は HID のコールバック(ホストからの GET_REPORT / SET_REPORT など)に応答できず、ホスト側から切断されることがある。
画面オフや他アプリへの一時的な切り替えで接続が切れないよう、**猶予時間の間だけ**フォアグラウンドサービス(type `connectedDevice`)で接続を保持する。

| 状況 | 動作 |
|---|---|
| ホストに接続(フォアグラウンド) | フォアグラウンドサービスを開始(接続中の通知を表示) |
| 接続中にバックグラウンドへ移行 | 猶予タイマーを開始 |
| 猶予時間内にフォアグラウンドへ復帰 | タイマーを止める。接続はそのまま |
| 猶予時間が経過 | 切断 → `unregisterApp` → サービス停止 |
| 最近使ったアプリから削除(`onTaskRemoved`) | 即座に切断してサービス停止 |
| 通知の「切断」ボタン | 即座に切断してサービス停止 |
| 未接続のままバックグラウンドへ移行 | サービスを停止し、登録を解除 |
| 猶予経過後にフォアグラウンドへ復帰 | 自動で再登録し、前回のホストへ再接続 |

サービスはバックグラウンドに移るときではなく、**接続した時点(フォアグラウンド)で開始する**。
Android 12 以降、バックグラウンドからフォアグラウンドサービスを開始(`startForeground` を含む)することは制限されているため。
サービスが動くのは「接続中」と「猶予時間中」だけで、それ以外では常駐しない。

- 猶予時間は設定で変更できるようにする(例: 1 分 / 5 分(既定) / 15 分)。無制限は設けない。
- 再登録から再接続までは数秒かかる。復帰時はその間「再接続中」を表示する。
- 追加の権限: `FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_CONNECTED_DEVICE`、`POST_NOTIFICATIONS`(Android 13 以降)。`connectedDevice` 型の開始には `BLUETOOTH_CONNECT` の許可が前提となる(Android 14 以降)。
- 通知には接続先、残りの猶予時間、「切断」ボタンを表示する。

### 7.5 権限と状態ごとの表示(v2.0)

ホスト選択画面の「Bluetooth で接続」のカードの中で、状態ごとに次のように表示する(画面デザインの仮案 1-a〜1-g)。

必要な権限:

| Android | 権限 | 確認 |
|---|---|---|
| 12 以降 | `BLUETOOTH_CONNECT`(登録・接続・ペアリング済み一覧)、`BLUETOOTH_ADVERTISE`(検出可能にする) | 実行時。どちらも「付近のデバイス」のため、ダイアログは 1 回 |
| 9〜11 | `BLUETOOTH`、`BLUETOOTH_ADMIN` | インストール時に自動で許可される |

機器の探索はしないため、`BLUETOOTH_SCAN` と位置情報の権限は使わない。

| 状態 | 表示 | 操作・回復 |
|---|---|---|
| 権限が必要 | 「付近のデバイス」の許可が必要な理由(位置情報は使わない旨を含む) | 「許可する」でシステムのダイアログを出す。説明はダイアログより前に出す |
| 権限がオフ(今後表示しない) | アプリの設定で許可するよう案内 | 「アプリの設定を開く」。`shouldShowRequestPermissionRationale` で 1 回目の拒否と区別する。画面に戻ったら権限を確認し直し、自動で先に進む |
| Bluetooth がオフ | オンにすると前回の PC に自動接続する旨 | 「Bluetooth をオンにする」で `ACTION_REQUEST_ENABLE`。状態の変化を監視し、オンになったら自動で先に進む |
| HID 対応の確認中 | 進み具合 | 最大 **5 秒**待ち、プロファイルが取得できなければ `Unsupported` |
| HID 非対応 | メーカーが機能を無効にしており端末の設定では変えられない旨、端末情報(メーカー・機種・Android のバージョン) | 対応状況の報告リンク(GitHub の issue)。USB 経路の実装後は USB のカードへ誘導する |
| 新規ペアリング: 検出可能 | 残り時間、PC 側の操作(Windows / macOS) | 検出可能にする時間は **120 秒**。「キャンセル」 |
| 新規ペアリング: 時間切れ | PC の一覧に出なかった場合の案内 | 「もう一度検出可能にする」 |

使用中(マウス・キーボード画面)のエラーは、操作面の左上に色の丸と文言で表示する(4.3)。

| `ErrorReason` | 表示する場所 | 文言 | 色 | 回復 |
|---|---|---|---|---|
| `CONNECTION_LOST` | メイン | 接続が切れました(再接続中…) | 赤 | 前回の PC へ自動で再接続 |
| `BLUETOOTH_OFF` | メイン / ホスト選択 | Bluetooth がオフになりました。オンにすると再接続します | 黄 | オンになったら自動で再接続(ホスト選択には戻さない) |
| `HOST_NOT_FOUND` | メイン / ホスト選択 | PC が見つかりません。PC の電源と Bluetooth がオンか確認してください | 赤 | 「もう一度」 |
| `HOST_REJECTED` | ホスト選択 | PC が接続を拒否しました。PC の Bluetooth 設定からこのスマホを削除し、ペアリングし直してください | 赤 | 新規ペアリングへ誘導 |
| `REGISTER_FAILED` | ホスト選択 | Bluetooth の準備に失敗しました | 赤 | 「もう一度」 |
| `UNSUPPORTED` | ホスト選択 | Bluetooth のマウス・キーボード機能に対応していません | 赤 | なし(報告リンク) |

- 赤は自動では直らない、または接続が使えない状態。黄はユーザーの操作で直る状態。色だけに頼らず、必ず文言を添える。
- 権限が使用中に取り消された場合は、Android の仕様でアプリのプロセスが終了する。次回の起動で「権限が必要」から始まるため、特別な対応はしない。

## 8. 表示言語

v2.0 は日本語のみとする。ただし文字列は最初からリソースに置き、v2.x で英語を追加する。以下は v2.x での構成。

- 日本語と英語に対応する。**日本語を優先**し、文言は日本語を正として作成してから英語を用意する。
- リソースの既定(`values/`)は英語、日本語は `values-ja/` に置く。端末の言語が日本語でも英語でもない場合(例: フランス語)に英語で表示するため。
- 文字列リソースは Compose Multiplatform のリソース機能(`composeResources/values*/strings.xml`)で管理し、iOS 版と共有する。
- Android 13 以降のアプリ別言語設定に対応する(`localeConfig`)。

## 9. 画面構成(Android)

v2.0 の画面構成:

```
ホスト選択(起動時の画面)
  前回のホスト / ペアリング済み一覧 / 新規ペアリング
  権限・Bluetooth・HID 対応の状態に応じた表示もここで行う
    ↓
メイン(上部に帯は置かない。下部にタブ列)
  ├ マウス
  ├ キーボード
  └ 設定への入口(タブ列の右端)
設定
  ホストごと: OS(Windows / macOS / その他)、キーボード配列(US / JIS)
  共通: 移動感度、スクロール方向、クリックボタンの表示、画面を点けたままにする
  ホストの切断・選び直し
```

- **オンボーディングは設けない。** 権限の要求、HID 対応のチェック、ペアリングの案内はホスト選択画面で、状態(`ConnectionState`)に応じて表示する。
- ホスト選択画面は接続方法(経路)ごとにカードを分ける(7.1)。v2.0 は「Bluetooth で接続」のカードのみ。「USB で接続」のカードは、USB 経路を実装した時点で表示する。
- 画面は**縦固定**とする。横向きは v2.x(13. 決定事項 9)。
- メイン画面(マウス・キーボード)では、システムの「戻る」操作でアプリを終了しない。誤操作で接続が切れるのを防ぐため。
- マウス・キーボード(v2.x ではショートカットパッド・メディアも)の各画面は `view/*` に置き、iOS 版と共有する。
- ホスト選択・設定画面・メインのタブ・画面遷移は `androidApp` に置く(骨格のため)。

v2.x で追加する画面・項目:

- メインのタブ: ショートカットパッド、メディア
- 設定: 加速、スクロール速度、触覚フィードバック、バックグラウンド時の猶予時間、表示言語、IME 入力

## 11. テスト

- Report Descriptor: バイト列のゴールデンテスト(各レポート長の検算を含む)
- `HidReportEncoder`: 端数の持ち越し、16 ビット超の分割、6 キー超のロールオーバー、押下 / 解放の順序

- `KeyboardLayout`: US / JIS の ASCII 全文字の変換表
- 実機テスト: Windows 11 / macOS(最新)への接続、各機能の動作
- CI(GitHub Actions)で PR ごとにビルド・単体テスト・lint を実行する(#71)

## 13. 決定事項

1. **高解像度スクロール(Resolution Multiplier)は v2.0 では見送る。**
   - 効果があるのは Windows / Linux のみ(macOS は通常のスクロールとして動作する)。
   - Report Descriptor の構成が複雑になり、誤るとスクロール自体が効かなくなるおそれがある。Feature レポート(`onGetReport` / `onSetReport`)の挙動も端末依存があり、検証コストが大きい。
   - v2.0 は 8 ビットの通常ホイールとし、端数の持ち越しで滑らかさを補う。`HidReportEncoder` はホイールの倍率を後から扱える作りにしておき、v2.x で Windows 向けの試験機能として再検討する。
2. **minSdk は 28 のまま**とする。`BluetoothHidDevice` が API 28 からのため、これより下げられない。上げる理由も現時点では無い。
3. **v2.0 は v1.0 Android アプリの置き換え(MVP)とする。** マウス・キーボード・ホスト選択・最小限の設定に絞り、それ以外は v2.x 以降に回す(1. 範囲)。
4. **オンボーディングは設けない。** 権限・HID 対応チェック・ペアリング案内はホスト選択画面で扱う(9. 画面構成)。
5. **「タッチパッド」と呼んでいた機能は「マウス」と呼ぶ。** 画面・タブの名前を、PC から見た役割で揃えるため(4. マウス)。
6. **キーボードの既定はアプリ内のキー配列とし、IME 入力は v2.x のオプションとする。物理キーボードには対応しない。** 物理キーボードがあるなら PC に直接つなげばよいため(5.2 入力方式)。
7. **v2.0 ではメイン画面を開いている間、画面を点けたままにする**(設定で切り替え可、既定: オン)。バックグラウンド時の接続保持を v2.x に回したため(7.3)。
8. **画面端の「戻る」ジェスチャー対策として、マウスの操作面の左右に余白を残し、メイン画面では「戻る」でアプリを終了しない**(4.3、9. 画面構成)。
9. **v2.0 は縦固定とし、横向きは v2.x で対応する**(#73)。優先度は高めとする。
10. **v2.0 の配布は Firebase App Distribution と GitHub Releases で行う**(#72)。Google Play には出さない。開発中は、デバッグ版(`jp.ikanoshiokara.pixelpilot.debug`)を main へのマージごとに App Distribution で配布する。手順は `docs/distribution.md`。
11. **接続状態は色と文言で示す。** 接続中は緑の丸と接続先、切断・エラーは赤の丸とエラーの内容(4.3)。
12. **`ConnectionState` は経路ごとの状態とし、ある経路が使えなくてもアプリ全体を使えない状態にはしない**(7.1)。Android でも USB 経路(デスクトップ版経由)を想定しているため。USB のカードは USB 経路の実装後に表示する。
13. **v2.0 は Bluetooth HID で PoC を行う。** USB は遅延・ジッターの面で優れるが、非 root の Android は USB HID デバイスになれず、デスクトップ版が必要になる。Bluetooth の遅延は実機で計測し、v2.x の優先順位の判断材料にする。
14. **権限・Bluetooth・HID 対応まわりの表示と流れは 7.5 のとおりとする。** 権限の説明はシステムのダイアログより前に出し、「今後表示しない」ではアプリの設定へ誘導する。検出可能にする時間は 120 秒、HID 非対応と判定するまでの待ち時間は 5 秒。
15. **モジュールは model / domain / view のレイヤーで分け、各レイヤーの中を機能ごとのモジュールにする**(10. モジュール対応、[v2.0 設計方針 7.](./v2.0.md#モジュール構成))。`TouchpadInterpreter` は UI ではなく `domain/input` に置く。ホスト選択・設定画面・メインのタブは骨格として `androidApp` に置く。ビルド設定は `build-logic` の convention plugin にまとめる。
16. **マウスのサブボタン(戻る・進む)は、1 本指の長押しで出す操作ダイアルから送る**(4.1、#98)。ほかの戻る・進むの操作(3 本指スワイプなど)は足さない。触覚フィードバックはダイアルが開いたときだけ v2.0 で入れる(クリック時の振動は v2.x のまま)。
